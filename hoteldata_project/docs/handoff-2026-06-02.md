# Handoff 2026-06-02

## Contexto general

Este proyecto está migrando una UI legacy `Jinja2 + CSS/JS` hacia un frontend Angular separado, manteniendo `FastAPI` como backend/API y dejando la lógica ETL / datos en Python.

El foco de esta sesión fue principalmente:

- seguir la migración frontend por módulos reales, no placeholders
- mejorar bastante la UI/UX y el lenguaje visual
- corregir mezcla incorrecta de roles/navegación
- recuperar coherencia entre frontend Angular y backend FastAPI

Adicionalmente, el usuario comentó que ayer probó `opencode` y `freebuff` por CLI. Ya no hay tokens ahí, pero sí hicieron cambios relevantes, sobre todo de diseño, UI y estructura visual. Este handoff debe asumirse sobre un repo que ya recibió trabajo de múltiples agentes.

## Forma de trabajo acordada

Durante esta etapa se trabajó con criterio de "skill-guided migration":

- evitar UI genérica tipo dashboard admin de escritorio
- evitar romper backend por inventar contratos
- migrar por responsabilidad
- reutilizar lógica legacy real cuando exista
- mantener diseño tipo app web / marketplace hotelero premium

Se insistió varias veces en:

- no saturar contexto innecesariamente
- reusar skills y estructura existente
- no tocar backend/docs salvo que fuera necesario para cerrar una migración real

## Objetivos de esta sesión

1. Mejorar el diseño global del frontend Angular para que se sienta como app web hotelera, no panel viejo.
2. Corregir flujos de login, sesión y navegación por rol.
3. Afinar la navbar superior global, branding y diseño glass.
4. Seguir la migración real de módulos administrativos.

## Qué no funcionó / problemas abiertos

### Problema 1: backend vivo desactualizado

El frontend nuevo de `Usuarios` y `Permisos` sigue fallando en runtime.

Síntomas:

- `Usuarios`: "No fue posible cargar los usuarios"
- `Permisos`: "Collection is not available in TA 02 CRUD"

Diagnóstico fuerte:

- eso indica que el backend activo no está usando todavía las rutas nuevas de admin
- al menos `Permisos` está cayendo en el router genérico de TA02 CRUD:
  - `/api/{collection_name}/{document_id}`
  - interpretando:
    - `admin` como collection
    - `permissions` como document id

Conclusión:

- el proceso backend que responde en `127.0.0.1:8000` no tomó el código nuevo
- probablemente hay que reiniciar el backend real

### Problema 2: Docker / backend restart bloqueado

Se intentó relanzar el backend por Docker:

- `docker compose -f docker-compose.local-mongo.yml up -d app`

Resultado:

- falló porque Docker daemon no estaba activo

Se intentó abrir Docker Desktop, pero esa acción fue rechazada por política de riesgo, además de que el usuario antes había pedido no gastar tiempo en Docker salvo necesidad.

Estado:

- el backend probablemente necesita reinicio manual o aprobación explícita para levantar Docker Desktop

### Problema 3: logo todavía inconsistente visualmente en runtime

Aunque el asset sí existe y compila, el usuario siguió viendo icono roto / caché vieja.

Posibles causas:

- `ng serve` viejo
- caché del navegador
- asset viejo cacheado
